# THE OSSUARY — клеточный бой на C++ / OpenGL

В существующую 3D-комнату встроен игровой прототип: выбор воина, разбойника или мага,
движение по клеткам, пошаговый бой с врагами, очки действий, навыки, экипировка и развитие.
Три последовательные встречи проходят в одной комнате; это демонстрация боевого модуля,
а не готовая система генерации этажей. Подробные правила и описание интеграции — в [COMBAT.md](COMBAT.md).

Интерактивная 3D-сцена для выбора графического направления университетской игры.
Расширенный склеп 28 × 22,4 единицы (627,2 вместо прежних 192 единиц площади) оформлен как рисованная иллюстрация: крупные пятна пигмента, цветные тени и тонкие контуры. Он показан в ортографической проекции: комнату можно
рассматривать с разных сторон, приближать и исследовать управляемым персонажем.

Исходники сцены и ресурсы находятся в этом репозитории. Готовая сборка создаётся локально.

## Быстрый запуск

Открыть папку проекта и дважды щёлкнуть **`launch-room.cmd`**.
Скрипт запускает готовую сборку `build/Release/finalprj.exe`; если её нет,
использует `build/Debug/finalprj.exe`. Автоматическую сборку он не выполняет.

Окно открывается размером **1440 × 900**. Его можно растянуть или развернуть.
Для комфортной работы предпочтительна сборка **Release**.

## Управление боевым прототипом

После запуска выберите класс мышью или **F1 / F2 / F3**. Вне боя герой идёт по клеткам
без затрат ОД. Враг замечает героя в радиусе 5 клеток при прямой видимости; также бой
можно начать клавишей **B**. Все живые враги комнаты вступают в бой одновременно.

| Действие | Управление |
| --- | --- |
| Идти по кратчайшему свободному маршруту | ЛКМ по клетке |
| Обычная атака | Q, затем ЛКМ по врагу; по умолчанию уже выбрана |
| Навык оружия | E, затем ЛКМ по врагу |
| Защита до следующего хода | F — 2 ОД |
| Выпить зелье, восстановить до 35 HP | H — 2 ОД в бою |
| Переключить меч / кинжалы / лук / посох | V — 2 ОД в бою |
| Сменить лёгкую броню на тяжёлую | I — только вне боя |
| Закончить свой ход | Пробел |
| Отменить маршрут исследования / режим навыка | Backspace; оплаченный боевой маршрут не отменяется |
| Сетка доступных клеток | G |
| Следующая встреча после победы | N |
| Восстановить начало встречи после поражения | R |
| Новый герой после трёх побед | F5 |
| Камера, приближение | ПКМ + движение мыши, колесо; 1 / 2 / 3 — ракурсы |
| Интерфейс, снимок, выход | Tab, F12, Esc |

Действия также доступны кнопками внизу окна. Наведение показывает маршрут, стоимость,
урон и причину запрета; карточка цели — её здоровье, броню и состояния. Интерфейс на английском.
Контрольная точка существует **в текущем запуске**; закрытие игры завершает сессию.

## Управление исходной графической сценой

Старый режим доступен командой `finalprj.exe --scene-only`:

| Действие | Клавиши |
| --- | --- |
| Движение персонажа относительно камеры | **W A S D** |
| Быстрое движение | **Левый Shift** + движение |
| Поворот и наклон камеры | Удерживать **правую кнопку мыши** и перемещать мышь |
| Поворот камеры влево / вправо | **← / →** |
| Приближение / отдаление | **Колесо мыши** |
| Общий вид / алтарь / слежение за персонажем | **1 / 2 / 3** |
| Показать занятые клетки | **G** |
| Магический импульс вокруг персонажа | **Пробел** |
| Скрыть / показать надписи | **Tab** |
| Вернуть исходную камеру и положение персонажа | **R** |
| Сохранить кадр | **F12** |
| Выйти | **Esc** или крестик окна |

Если при повороте камеру закрыли стены, **R** вернёт исходный открытый ракурс.
В заголовке окна отображается частота кадров.

## Что есть в сцене

- Каменный пол из отдельных плит, швы, трещины и декоративная окантовка.
- Объёмная кладка, стрельчатые арки, глубокие ниши с решётками, пилястры и карнизы.
- Ступени и алтарная площадка, сундук, бочки, ящики и мелкий реквизит.
- Персонаж в доспехах и базовое ограничение движения у части крупных препятствий.
- Мерцающее освещение факелов, холодный основной свет и мягкие тени основного света и тени от двух жаровен у алтаря.
- Процедурная фактура камня, дерева и металла.
- Частицы огня, искры, пыль, низкая дымка и магический импульс.
- Статуи в капюшонах, каменная печать, саркофаг, ткань и низкие разрушенные укрытия.
- Плавный разгон, торможение и поворот героя, согласованный с движением шаг, движения рук, дыхание и колебания плаща.
- Плавное приближение и переходы между ракурсами камеры.
- HDR-отрисовка, свечение ярких участков, контактное затемнение и виньетка.

Боевая система и пять типов врагов реализованы отдельным модулем. Экипировка переключается
из готового набора; полноценного инвентаря, лута и импорта скелетных анимаций пока нет.
Анимация героя процедурная, с отдельными трансформациями конечностей и сеткой плаща.

## Как устроены модели и материалы

Архитектура, предметы и персонаж создаются программно из треугольников:
скошенных каменных блоков, цилиндров, сфер и других простых форм.
Детализация материалов рассчитывается в шейдере по координатам поверхности.
Это настоящая 3D-сцена, отрисовываемая OpenGL в реальном времени.

PNG-файлы в `assets/` используются для надписей интерфейса. При сборке CMake
копирует папку `assets` рядом с исполняемым файлом. При переносе готовой сборки
сохранять эту папку рядом с `finalprj.exe`.

## Сборка на Windows

Нужны:

- Visual Studio 2022 или новее с рабочей нагрузкой
  **«Разработка классических приложений на C++»**.
- Windows SDK и компонент **«Средства C++ CMake для Windows»**.
- CMake 3.20 или новее.
- Видеодрайвер с поддержкой **OpenGL 3.3 Core**.

В **Developer PowerShell for Visual Studio**, находясь в папке проекта:

```powershell
cmake -S . -B build
cmake --build build --config Release --parallel
.\launch-room.cmd
```

Либо открыть папку проекта в Visual Studio через **Файл → Открыть → Папка**,
выбрать конфигурацию **Release** и цель **finalprj.exe**, затем собрать и запустить.
Visual Studio может использовать собственную папку сборки `out/`; в таком случае
запускать приложение из IDE, поскольку `launch-room.cmd` ищет сборки в `build/`.

## Проверка и снимки

```powershell
ctest --test-dir build -C Release --output-on-failure
```

Проверка создаёт скрытое настоящее окно OpenGL, отрисовывает 45 кадров,
проверяет изменение размеров окна и сообщает скорость отрисовки,
проверяет ошибки OpenGL и основные признаки непустого изображения:
яркость, разброс значений пикселей и долю освещённых пикселей.
Нужны рабочий графический драйвер и графическая сессия.
Эта проверка не заменяет визуальный осмотр сцены.
Отдельный тест проверяет препятствия, границы комнаты и скольжение вдоль них. Тест анимации проверяет постоянную топологию, конечность координат и непрерывность движения на двухсекундном цикле.

**F12** сохраняет снимок в формате **PPM** в папке `captures` рядом с программой.
Для обычной сборки Release это `build/Release/captures/`.
Проверочный запуск также сохраняет там `smoke.ppm`.

Отдельный снимок размером 1920 × 1200 можно создать без видимого окна:

```powershell
.\build\Release\finalprj.exe --capture .\room-preview.ppm
.\build\Release\finalprj.exe --view altar --capture .\altar-preview.ppm
.\build\Release\finalprj.exe --view hero --motion --time 1.2 --capture .\walk-preview.ppm
```

Приложение автоматически завершится после сохранения кадра. В режиме снимка
время эффектов фиксируется, чтобы сравнивать разные версии сцены.

## Библиотеки и работа без интернета

| Библиотека | Версия | Назначение |
| --- | --- | --- |
| GLFW | 3.5.1 | Окно, контекст OpenGL, клавиатура и мышь |
| GLAD | генератор 2.0.8 | Загрузка функций OpenGL 3.3 Core |
| GLM | 1.0.3 | Векторы, матрицы, камера и преобразования |
| stb_image | 2.30 | Чтение изображений интерфейса |

Исходники библиотек уже находятся в `third_party/`. После установки компилятора,
CMake и драйвера **интернет для сборки и запуска не нужен**. Подмодулей и загрузок
при запуске нет. Точные ревизии и лицензии перечислены в `third_party/README.md`.
OpenGL предоставляет видеодрайвер; копировать `opengl32.dll` в проект не требуется.

## Основные файлы

- `src/main.cpp` — окно, камера, ввод, движение, освещение, частицы, постобработка и снимки.
- `src/combat.hpp`, `src/combat.cpp` — правила боя, поиск пути, ИИ, классы и развитие.
- `src/combat_view.hpp` — ввод, анимация перемещения, враги, сетка и динамический HUD.
- `tests/combat_test.cpp` — правила и полное прохождение трёх встреч каждым классом.
- `src/architecture.cpp` — пол, стены, арки, колонны, ступени и основание.
- `src/props.cpp` — предметы окружения и персонаж.
- `src/scene.hpp` — вершины и функции построения геометрии.
- `src/material_shader.hpp` — материалы и освещение поверхностей.
- `assets/` — изображения надписей интерфейса.
- `CMakeLists.txt` — сборка и копирование ресурсов.
- `launch-room.cmd` — запуск готовой Windows-сборки двойным щелчком.

## Другие системы

Исходники используют GLFW и OpenGL 3.3. На Linux нужны компилятор C++17,
CMake и пакеты разработки оконной системы; на macOS — Xcode Command Line Tools
и CMake. Например, для Ubuntu/Debian с X11:

```sh
sudo apt install build-essential cmake xorg-dev
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DGLFW_BUILD_WAYLAND=OFF
cmake --build build --parallel
./build/finalprj
```

Для macOS используются те же команды CMake без параметра `GLFW_BUILD_WAYLAND`.
Сборка этой локальной версии проверяется на Windows.

## Единая сетка объектов

Пол состоит из 20 × 16 квадратных клеток размером 1,4. Размещение и коллизии используют `src/scene_layout.hpp`. Статуя, жаровня, бочка, стопка ящиков или книг занимают 1 × 1 клетку, сундук — 2 × 1, саркофаг — 1 × 3, укрытие — 3 × 1, площадка алтаря — 4 × 3. Модели вписаны в эти области с небольшим отступом. Крайний ряд клеток зарезервирован под границу комнаты.

Герой увеличен в 1,45 раза относительно предыдущей версии. В игровом режиме он перемещается
между центрами клеток по кратчайшему маршруту, обходя предметы и живых участников.
Диагональных шагов нет. В `--scene-only` сохранены свободное движение и прежняя отладочная сетка.

Камень использует `assets/stone-paint.png`, созданную через imagegen; описание и исходный запрос находятся в `assets/README.md`.

## Обновлённые анимации и тени

Походка использует двухзвенную обратную кинематику ног: 62% цикла стопа опирается на пол, затем переносится с плавным подъёмом и перекатом. Длина шага согласована с фактическим перемещением; корпус переносит вес, плечи вращаются навстречу тазу, голова стабилизирована, а плащ запаздывает. Скорость ходьбы 1,6, ускоренного движения 2,6 единицы в секунду. Это процедурная анимация, без захвата движений.

Общий заполняющий свет уменьшен на 35%, направленный — примерно на треть. Основная тень фильтруется с расширением полутени при удалении от препятствия. Две жаровни у алтаря используют кубические карты глубины с мягкой фильтрацией; остальные огни дают локальное освещение без отдельных карт теней. Геометрия комнаты в кубических тенях кэшируется, а герой обновляется каждый кадр. При добавлении подвижной мебели или источников света этот кэш потребуется обновлять. Колебания знамени отражаются в основной динамической тени, но не в кэшированных тенях жаровен.
